## ADDED Requirements

### Requirement: Option presentation supports readable functional operation
Engine Options and Post FX Options SHALL present readable identity, origin, registry-driven rows, distinct focus/current markers, lifecycle and failure states, and action guidance. Figma nodes `48:173` and `48:207` SHALL guide hierarchy and interaction. Exact typography, spacing, coordinates, and pixel correspondence SHALL NOT be completion gates; native functional operation SHALL remain required.

#### Scenario: Engine Options reference comparison
- **WHEN** ready, focused/current-separated, unavailable, loading, and failed Engine Options states are reviewed in the native application
- **THEN** native review SHALL verify the option identity header, Engine origin annotation, readable row order, current and focus markers, state text and shapes, persistent Utility, and footer guidance using live Figma node `48:173` as a guide

#### Scenario: Post FX Options reference comparison
- **WHEN** occupied, empty, duplicate-capability, focused/current-separated, unavailable, loading, and failed Post FX Options states are reviewed in the native application
- **THEN** native review SHALL verify the exact slot origin, option and empty rows, readable row order, current and focus markers, state text and shapes, persistent Utility, and footer guidance using live Figma node `48:207` as a guide

#### Scenario: Registry fixtures do not define visual limits
- **WHEN** the production registries provide different counts, labels, duplicate effects, or availability states from the Figma examples
- **THEN** the same authored option grammar SHALL arrange the exact projected rows without changing their stable identity, canonical order, or reducer-owned behavior

### Requirement: Option presentation preserves accepted responsive behavior
Changes to option layout behavior SHALL exercise one unchanged serialized Engine Options document and one unchanged serialized Post FX Options document through varied constrained, intermediate, and expanded widths, representative heights, and enlarged text. Named viewport captures SHALL remain compositional examples rather than static page contracts or the only resize evidence.

#### Scenario: Resize-only exploration
- **WHEN** an open option document is resized repeatedly through varied widths without physical or semantic input
- **THEN** subject, exact origin, focus, current option, option order, lifecycle, return identity, valid actions, and generation SHALL remain byte-for-byte equivalent while every observed native composition retains reachable required content and no resize-derived action

#### Scenario: Reflow remains robust
- **WHEN** live resize crosses a layout or content-driven reflow
- **THEN** observations on both sides of that reflow SHALL retain one focus, the canonical minimum target size, bounded scrolling, no required-content overlap, and no document-level horizontal overflow

#### Scenario: Completion claim is bounded by evidence
- **WHEN** native operation identifies an unresolved functional defect
- **THEN** the affected workflow SHALL remain reported as incomplete and the measured gap SHALL remain explicit
